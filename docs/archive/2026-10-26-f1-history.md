# F1: pending input at Undo/Redo boundaries

The October 26 project review reproduced loss of the latest text when Undo ran before the 400ms history debounce. `createEditingController.moveHistory()` now cancels the timer and records the current state before moving the history cursor. Existing fingerprint checks avoid duplicate entries; new edits after Undo replace the redo branch.

## Regression coverage

- `tests/editing-history.test.mjs`: real editing/session factories with a deterministic clock. Exact text at 0, 1, 199, 399 and 400ms; continuous input grouping; canceled callbacks after Undo; clean baseline; duplicate prevention; redo branch replacement.
- `scripts/check-drafts-browser.mjs`: real title input and Undo/Redo clicks on desktop and mobile fixtures; latest text survives Redo/reload/recovery; undo-to-clean removes the recovery draft before reload. Only the history debounce is held to make pending-input clicks deterministic; storage and lifecycle behavior remain real.

Before the source fix, six of seven new unit cases failed; the 400ms case passed. After the fix, all seven pass. Browser fixtures block external requests and use synthetic data.

Current behavior and test procedures are documented in User Guide, Project Guide and Operations. The original review and its evidence remain historical. No document moves, dependency changes, schema changes or Pages exclusion updates are required.
