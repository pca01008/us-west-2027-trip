# A · Daylight 후속 세션 인계 — 2026-10-22

## 다음 세션의 출발점

**A · Daylight 초안을 개선하며 검토하는 단계다. 운영 앱 적용은 아직 승인되지 않았다.** 현재 공개된 초안을 기준으로 사용자의 다음 피드백을 받는다. 세 가지 방향을 다시 고르거나 운영 `index.html`을 초안으로 교체하지 않는다.

이 문서는 [10월 21일 인계](2026-10-21-daylight-handoff.md) 이후의 변경을 포함한 최신 인계다. 이전 문서의 “확인 사항은 펼쳐보기”, “시간표 미연결” 설명은 당시 상태이며 현재 A안에는 해당하지 않는다.

사용자는 **원격에서 보고 있어 로컬 미리보기에 접근할 수 없다.** 화면을 보여줄 때는 공개 HTTPS 주소를 제공한다.

- [현재 A안 초안](https://pca01008.github.io/us-west-2027-trip/ui-preview/a.html?v=22ecee3)
- [세 안 비교 페이지](https://pca01008.github.io/us-west-2027-trip/ui-preview/)

`v=22ecee3`는 캐시 구분용이며 해당 커밋의 고정 스냅샷 주소는 아니다. 이후 배포되면 같은 경로의 화면도 바뀐다.

## 유지할 합의와 제약

- **기존 웹사이트의 기능·목적을 바꾸지 않는다. 불가피한 변경은 먼저 사용자에게 확인한다.** 초안에 연결되지 않은 기능을 제거하기로 합의한 것이 아니다.
- 사용자가 적용 범위를 직접 **“A안 초안을 먼저 개선하고 검토”**로 선택했다. 초안 배포와 운영 화면 적용을 구분한다.
- 여행 전 PC 계획·예산 편집과 여행 중 모바일 조회를 같은 비중으로 고려한다.
- 사용자 두 명의 실제 필요에 맞게 기존 패턴·의존성을 활용한다. 복잡한 자동 추천이나 별도 인프라를 임의로 추가하지 않는다.
- A의 세이지·흰 바탕과 녹색 강조를 유지한다. B/C는 비교 기록으로 보존하며 C의 3일 보드 결합은 승인되지 않았다.
- 실제 기능·저장·복구 동작은 [사용자 안내서](../USER_GUIDE_KO.md), 내부 구조는 [기술 설명서](../PROJECT_GUIDE_KO.md)가 기준이다.

시간표는 운영 코드의 순수 시간 해석·분류·겹침 계산을 재사용한다. PC는 전체, 모바일은 1일이 기본이고, 날짜 제목으로 1일 보기에 진입한다. 1일 보기는 첫 시간 지정 일정이 보이는 위치에서 시작하며 상세에는 설명·주의사항·지도·사진을 표시한다. 운영 앱과 Supabase 공유 데이터는 수정하지 않았다.

상세 경위: [1차 개선](2026-10-21-daylight-refinement.md), [사용성 개선](2026-10-22-daylight-usability.md).

## 가장 최근 질문과 아직 결정하지 않은 것

사용자는 다음 두 가지의 선정 의도를 물었다.

1. 일정에서 라스베이거스 날짜인데 왜 `LA에서 머무는 곳`이 나오는가?
2. 준비 탭의 `먼저 확인해요`와 LA 숙소는 어떤 기준으로 선정되는가?

이미 전달한 답변:

- `concepts.js`의 `lodgings()`는 West Hollywood 숙소 사진·주소·지도 링크를 보조 영역에 배치해 보기 위한 **고정 예시**다. 일정과 준비에서 같은 함수를 사용하고 날짜를 참조하지 않으므로 라스베이거스 날짜에도 나온다.
- `prep()`의 `먼저 확인해요`는 캐니언 투어의 캐리어·호텔 짐 보관 주의를 수동으로 넣은 고정 문구다. 날짜·우선순위·체크 완료 여부에 따른 선정 로직은 없다.
- 두 블록은 이번에 **설명만 했고 선정 방식은 변경하지 않았다.** 날짜에 맞는 숙소 표시, 카드 제거, 미완료 항목 우선 노출 중 어느 방향도 합의되지 않았다.

이 두 블록이 자연스러운 다음 논의 지점이지만, 자동 선정 구현이 이미 요청되었다고 간주하지 않는다. 사용자의 다음 지시를 따른다. 마지막 수정 화면에 대한 최종 디자인 승인도 아직 받지 않았다.

## 초안의 남은 한계

- `data.js`는 기본 `trip-config.js`의 표시용 스냅샷이다. 최신 서버 공유본을 조회하지 않는다.
- 첫 화면은 2027년 1월 25일 여행 중 예시다. 시계·다음 일정 강조·체크 상태·가상 지출 3건·도시 표기·숙소 등에 고정값이 있다. 실제 여행 전·중·후 화면 선택 로직으로 해석하지 않는다.
- 준비 체크는 페이지 메모리에만 유지된다. 새로고침 후 보존·서버 저장을 제공하지 않는다.
- 설정 메뉴의 편집·저장·버전·불러오기·내보내기·테마 버튼은 배치 검토용 비활성 버튼이다. 인증·공유 저장·초안 복구·오프라인·다크 테마는 아직 연결하지 않았다.
- 시간표를 연결했어도 운영 기능 전체를 이식한 것은 아니다. 실제 운영 적용 시 기존 기능과 데이터 무결성을 유지하는 연결·회귀 검증이 필요하다.
