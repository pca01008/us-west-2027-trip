# A · Daylight 사용성 개선 — 2026-10-22

## 요청과 범위

사용자는 일정·준비 탭의 숙소와 주의 안내의 선정 이유를 질문하고, 준비 탭 진입 시 맨 위로 이동, 가계부 카테고리 식별, 시간표 전환 버튼 개선을 요청했다. 기존 합의대로 A안 초안에만 적용한다. 운영 `index.html`과 공유 데이터, B/C의 화면 동작은 변경하지 않는다.

## 고정 예시 설명

`lodgings()`는 LA 숙소 사진·이름·일정·지도 링크를 하드코딩해 일정과 준비 화면에서 재사용한다. 숙소 정보를 보조 영역에서 빠르게 확인하는 배치를 보여주려는 예시로, 선택 날짜에 반응하지 않는다. 따라서 라스베이거스 날짜에도 LA 숙소가 표시된다.

`prep()`의 `먼저 확인해요`도 캐니언 투어의 캐리어·호텔 짐 보관 주의를 수동으로 넣은 예시다. 준비 완료 상태나 날짜를 통한 우선순위 계산은 없다. 이번 요청에서는 두 블록의 선정 이유를 설명했으며, 자동 선정 기능을 추가하거나 여행 내용을 변경하지 않았다. 현재 초안의 한계는 [운영 안내서](../OPERATIONS_KO.md#ui-concepts)에 명시했다.

## 변경

- 준비 목록 이동 버튼과 준비 메뉴 모두 페이지 맨 위로 이동하고 제목에 포커스를 둔다. 이미 준비 탭에서 아래로 읽은 뒤 준비 메뉴를 다시 눌러도 맨 위로 이동한다. 체크 상태는 유지한다.
- 가계부는 카테고리명을 색상 라벨로 표시한다. 모바일에서 숨기던 카테고리를 항목명 아래에 배치하고 항목·금액의 글자 크기를 높였다. PC는 기존 별도 열을 유지한다. 색상에 의존하지 않고 텍스트로도 구분할 수 있다.
- `일별 일정 / 시간표`는 아이콘과 밑줄로 선택 상태를 표현한다. `1일 / 전체`는 옅은 바탕의 작은 선택 영역으로 분리했다. 보기 방식과 범위가 같은 강도의 버튼으로 반복되던 문제를 줄였으며, 기존 선택 상태·날짜 유지·키보드 동작은 보존했다.

## 확인

- `node docs/ui-concepts/capture.mjs`: Chromium에서 A/B/C의 PC·모바일 탐색·체크·필터·날짜 이동 통과.
- 준비 진입·재선택의 스크롤 0, 제목 포커스, 체크 상태 보존, 카테고리 표시·필터와 키보드 시간표 진입 검증을 추가했다.
- 360·390·768·1280·1440px 가로 넘침 검사 통과. A 가계부의 카테고리 가시성도 확인했다.
- PC·모바일 가계부와 시간표 캡처를 직접 검토했다. Impeccable 기계 검사 결과는 빈 목록이었다.

현재 운영 기능의 사용법과 구현은 바뀌지 않아 사용자 안내서와 기술 설명서는 유지한다. 캡처·생성본·배포 절차는 [운영 안내서](../OPERATIONS_KO.md#ui-concepts)를 따른다.
